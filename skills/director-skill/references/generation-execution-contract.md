# 生图执行合同：generation-hard-rules-v1

这份合同解决一个明确的分层错误：规则不能只出现在审核报告、纠错说明或内部 audit 字段里，实际提交给图像模型的 Prompt 必须携带同一套规则。编译器可以压缩叙事铺陈，但不能压缩下列生图硬锁。画面硬清洁词固定为“无字幕、无水印”。

## 生图请求的唯一事实源

每一次 `image_generation_gate.py authorize` 都必须读取：

- 编译器写出的 canonical Prompt 全文，而不是摘要、旧 Prompt、审核备注或“按上次要求”这类指代；
- `GENERATION_HARD_RULES_V1` 标记和七段 Prompt 结构中的目标、产品与生图硬性规则段；
- 精确原始首帧、同景深尺度导引图、授权人物身份参考、批准产品参考和当前可见包装面的批准母版，全部按文件哈希绑定；
- 当前 `library/correction_memory.json` 的哈希和适用规则全文。规则文件变动后必须重新编译和授权，旧授权不能继续生成。

授权回执会保存 Prompt 全文、Prompt 文本哈希、纠错记忆哈希、适用纠错规则和必需图像输入。图像工具收到的文本必须与回执全文逐字一致；不能只传 `prompt_file` 路径而由工具或人工重新概括。

## 必须写入实际生图 Prompt 的规则

1. 产品替换：只保留项目锁定目标产品；原视频旧食品、旧包装、旧品牌/印刷全部清除，不得把旧产品的轮廓、颜色、材质或尺度带入目标。精确首帧声明 `product_visibility=absent` 时，首帧保持目标产品数量为 0，不得提前出现后续产品或零售盒。
2. 产品一致性：跨镜头、跨人物、跨场景沿用同一批准产品身份；榴莲大福使用约 7 厘米、同景深锚点和像素计划，不接受“看起来差不多”的文字估算。
3. 产品质感：榴莲大福保持暖奶白至浅象牙白的细腻糯米粉雾皮和连续暖金黄果泥，只有少量稀疏软纤维；禁止石头、塑料、颗粒团、蜂窝、孔洞、液流和长拉丝等错误质感。
4. 换脸：只使用授权身份参考；人物身份与产品替换在需要时同一请求原子执行，同时保持原片发型、身体、服装、姿势、机位、光照、遮挡和手指数量，不出现头身错配。
5. 包装：只投射当前镜头已批准且哈希绑定的可见层级/可见面母版；独立袋、零售盒和运输箱不可互换，不能保留原包装，不能凭空发明包装结构、品牌字样或图案。
6. 原片连续性：从精确原始首帧生成，保留原构图、动作、空间遮挡、背景、光线和镜头节奏；失败候选、审核截图和旧 Word 图只能作诊断或构图依据，不能作为下一轮生图输入。
7. 画面清洁：全图到最后一帧无新增字幕、水印、贴纸、平台 UI、无关品牌或文字；几何尺度导引图的青色轮廓、十字、标签和文字不得渲染进成品。
8. 返工写回（用户反馈写回）：用户指出的产品、大小、质感、换脸、包装、原产品残留、水印字幕等问题必须先写入 `correction_memory.json`，再编译新的 canonical Prompt。相同请求指纹的失败结果禁止盲重试。
9. 成品晋级：`approved_candidate` 只是 QA 通过的候选，不是最终事实源；只有带 `status=user_approved`、展示回执和候选字节哈希的用户批准记录，才能由 `image_generation_gate.py promote` 写入 `approved_generation_first_frame`。

## 分层规则

审核可以发现问题，但审核报告不再是生图规则的唯一载体。审核结论必须通过反馈写回进入纠错记忆，下一次 Prompt 必须逐字携带对应指令；如果 Prompt 缺少上述硬锁，授权阶段直接阻断，不消耗一次生图调用。

Agent 仅做编排和状态传输，不得作为规则解释器或二次 Prompt 作者。生图调用链为“canonical Prompt + 产品知识库 + 当前纠错记忆 → 授权回执 → 图像工具”，中间不再增加一层人工摘要；Agent 传输的文本和图片必须与授权回执逐字、逐文件一致。

## 单镜返工通道

全量 `pipeline.py compile` 适合最终交付快照，不适合修一张失败图。单镜返工使用 `pipeline.py compile-shot --shot-id <Sxxx> --unit-id <SRCxxx|ADDxxx>`：它复用同一编译器、产品知识、纠错记忆和精确源帧，但把结果写到 `review/shot-retries/<run-id>/`，不改写其他镜头的 Prompt、全局 generation pack 或全局交付回执。授权、结果记录和用户批准仍然按这个 `shot_id/unit_id` 独立绑定；只有最终 Word/整片交付时才重新生成全量快照。

历史项目若把反馈存成 `scope=all_frames` 或把正文存成 `rule`，读取和迁移阶段会按固定映射归一为 `project/product/style/shot + instruction + active`，并把原字段保留为 `legacy_scope` 供审计。归一化前不得把该反馈判作“没有规则”。
