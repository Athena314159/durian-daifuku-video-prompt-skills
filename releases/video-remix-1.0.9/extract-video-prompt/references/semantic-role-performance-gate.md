# 角色、空间与活人感语义门

这份门禁用于防止“结构完整但人物、动作和表演写错”。它不能替代逐帧观看，但会规定必须保存的证据和不能越过的决策。

## 1. 三层事实源

### 不可覆盖事实

用户明确纠正、可见像素、同步口型和可定位的原声。后来的语义猜测不得覆盖。

### 可推断事实

持机视角、手从哪里进入、人物看向哪里、递接关系、称谓和上下文。推断必须写证据与置信度。

### 待确认事实

仅凭衣着、发型、体型、音色印象或对话套路得到的性别和关系。未确认前保留 A/B/C，不得写入完整 Prompt。

证据冲突时按：用户明确纠正 > 原声与可见口型 > 动作/持机/手部来源 > 原字幕提示 > 对话语义。无法消解时询问用户，不投票、不凭常识补齐。

## 2. 角色镜像测试

建立初版映射后，强制把 A/B 对调一次并检查：

- 哪些台词仍然仅靠“听起来像”才能成立；
- 哪些动作与可见口型、手部来源、持机关系发生冲突；
- 用户明确纠正是否被旧推断覆盖。

如果对调后仍无法从证据排除一种方案，身份未锁定。角色镜像测试用于暴露假设，不用于擅自决定性别。

## 3. 逐句真值表

每句建立：

```text
原句：今天七夕几点了才回来？
说话人键 / 用户称呼：A / 女生
声源：镜头后现场对白
可见口型：否
动作主语：男生
同步视觉证据：男生停下动作，抬眼看向镜头后的女生
```

逐句核验四个问题：

1. 这句话是谁发声，而不是画面里谁在动？
2. 发声者是否需要可见口型？
3. 同时发生的动作是谁做？
4. 画面用什么证据让观众知道这句话落在谁身上？

不要把“说话人”和“动作主语”自动设为同一个人。

## 4. 空间不变量

角色锁一旦写明“女生全程镜头后”，所有分镜都继承：

- 女生不能出现脸、侧脸、嘴、身体、影子、镜面倒影、屏幕反射或自拍角度；
- 女生可以通过镜外现场声音、持机轻微反应、镜外空闲手或男生的目光落点存在；
- 男生与她交流时，视线落在镜头后真实眼睛位置，不是盯镜头玻璃，也不是看向不存在的画外点；
- 递物或喂食时，男生把产品送出画面边缘，咬合发生在镜外；同一颗产品以新增自然咬口返回画面；
- 若原片连女生的手也不可见，就不擅自增加手；若可见，记录哪只手、从哪侧进入和离开。

“为了证明咬了一口而展示女生嘴部”是空间违约，不是必要展示。

## 5. 人物—身体—动作—物体状态门

每拍先列：

```text
人物 | 身体部位 | 动作 | 物体 | 起始状态 | 结束状态 | 视线 | 时间
```

检查：

- 左右手是否已经占用；
- 承重、开盒、拿取、递出、喂食能否由当前空闲手完成；
- 嘴是否正在说话、咬食、闭口咀嚼或吞咽；
- 产品是否还是同一颗，数量、位置和破损状态是否连续；
- 结果前是否有可见前置动作。

不限制互不冲突的动作数量。只有同一资源在同一时间执行互斥动作、动作缺因果前置，或真实时长装不下时才拆镜。

## 6. 原片动作镜像表

任何“吃、咬、撕、递、接、开、拿、放、抬头、回看、后退、停顿”等可见动作都要逐项映射。尤其是原片人物正在吃时，Prompt 必须写：

- 原片实际可见的食物接近口部；
- 原片实际可见的张口时机；
- 原片实际可见的牙齿接触、咬入或脆断；
- 原片实际可见的产品离嘴；
- 原片能看清时，咬口或断面如何形成；
- 原片实际可见的闭口咀嚼，以及只有原片确实存在时才写的吞咽或后续反应；
- 说话发生在咬前、闭口咀嚼结束后，还是由画外音覆盖吃食动作。

不能用“品尝一下”“吃得很开心”概括动作链。

原片吃食链不是固定模板。逐镜保存 `required_phases`，只要求复刻可观察阶段；原片没有吞咽、喉结动作、闭眼、点头、满足笑或“嗯～”时，不得为了“完整咬食链”强制增加。人物完成原片可见的闭口咀嚼、嘴部重新可清楚发音后，可以下一拍马上说新版口播，不必额外等待一个虚构吞咽或吃后反应。

### 吃食与屏内口播时间门

- 咬合和闭口咀嚼期间，吃食者的嘴被动作占用，不得同一时间段说完整屏内口播。
- 吃食动作段与说话动作段必须分别标注起止时间；后一段可以紧接前一段，但不能重叠。
- 产品已经离嘴并不自动等于能说话；仍在闭口咀嚼时继续保持口部占用。原片可见咀嚼结束、口型恢复后即可说话。
- 画外音可以覆盖吃食动作，但不得伪装成吃食者同步口型；声源、说话人和口型需求仍按角色锁执行。

### 食欲感从原片证据推导

“吃得香”不是追加统一反应模板。逐帧观察并只写原片或用户明确新增的可见/可听信号：张口幅度、入口前期待视线、牙齿接触阻力、脆断瞬间、产品离嘴速度、闭口咀嚼次数与腮部运动、空闲手在下巴下方承托、克制碎屑、清脆声、呼吸变化和说话恢复点。用动作幅度、节奏和材质反馈让镜头有食欲，不用虚构吞咽、闭眼陶醉、夸张点头或统一“嗯～”。

## 6.1 全源分镜覆盖与短分镜合并门

先建立按原片时间排序的 `source_shot_inventory`。每个源分镜保存：唯一 ID、绝对起止时间、可见动作、原始首帧、批准分镜图。审核顺序不是“保留主要动作”，而是逐项证明每个源分镜都被映射、做图并进入最终 Word。

当源分镜不足4秒时：

1. 不能删掉、跳过或用相邻分镜的图冒充；
2. 只与 inventory 中时间相邻、空间连续、动作因果可衔接的源分镜合并；
3. 合并生成镜不少于4秒，镜内按原顺序重排 action beat；
4. 每个源 ID 的绝对时间、动作和批准图仍单独保存并在同一 Word 章节展示；
5. 分镜描述明确原片节奏如何与新版口播落点结合。

合并不是删除，也不是把多个源分镜概括成一个“人物展示产品”。任一源 ID 未覆盖触发 `SOURCE_SHOT_COVERAGE_INCOMPLETE`；不足4秒源镜未合法合并触发 `SHORT_SOURCE_SHOT_NOT_MERGED`；跨越 inventory 或颠倒顺序触发 `NONADJACENT_SOURCE_SHOT_MERGE`。

## 6.2 30 秒视频的三个非连续吃食事件

原视频总时长达到30秒时，最终至少三个吃食事件。这里的“事件”是一次完整的节奏点，不是三张连续图，也不能把同一次吃食的连续切换镜拆成三个计数。

- 先按时间连续性和同一次入口/咬合/离嘴/咀嚼关系归并原片事件。
- 原片已有三个或以上事件：全部保留，不新增吃食事件。
- 原片不足三个：只补到三个；新增位置由新版口播语义转折、原片剪辑停顿、产品证明需求和前后产品状态共同决定。
- 三个目标事件必须使用不相邻的生成镜 ID，分散到不同 `narrative_section`；每个事件记录 `rhythm_anchor` 和 `revised_script_anchor`。
- 每个原片事件记录真实 `required_phases`；新增事件也需写清设计阶段，但不得借模板把吞咽或吃后反应变成默认必选。

## 7. 叙事优先的活人感六层门

六层的意义是建立原片人物表演的因果模型，不是把 Prompt 切成六个栏目。先回答完整镜头的导演问题：原片这一刻发生了什么；人物在回应谁或什么；起始心理状态是什么；哪一个可见/可听事件触发变化；人物此刻想完成什么；情绪如何转折并落到下一拍；这个过程给观众什么感受。然后把适用六层融入同一条动作与情绪曲线。

内部分析分为三层：

1. **可观察事实**：原片时间、人物/物体动作、视线落点、五官变化、受力、呼吸、停顿、声源和口语特征。
2. **有证据的解释**：人物意图、关系张力、情绪基线、触发、转折和叙事落点；每项解释至少引用一个事实，不把推断冒充像素事实。
3. **正向导演执行**：把事实与解释翻译成生成模型可拍摄的主语、时间、动作、强度、节奏和可见结果。

完整编译时，只输出本镜可观察且适用的情绪触发、视线、五官、身体/手部准备、呼吸/停顿、声音/口语及因果动作。身份锁、产品物理、包装、摄影、负面限制和跨镜通用模板不得冒充表演。无可辨认正脸时不虚构五官和视线。表演占比默认只作诊断，只有用户或交付契约明确启用时才按 **40%–50%** 阻断。

### 六层写作顺序

先写一段连续的 `原片叙事复原`：`情境 → 触发 → 人物意图 → 主动作 → 感官反馈/对方反应 → 情绪转折 → 镜头落点`。随后按镜内时间写 action beat，并在动作发生的位置嵌入适用六层。禁止先写六个标题，再各填一段互不衔接的形容词。

每条六层执行句至少包含：`人物主语 + 触发或时间 + 可见/可听变化 + 对下一动作的作用`。例如“听到镜后追问后，他夹盒的手先停半拍，视线从盒面抬到镜后人物，压住的笑意随眉峰短促抬起而露出，随后带着想证明产品的轻快劲把盒口转向镜头。”这是一条完整叙事动作，可以同时承载视线、五官、手部、停顿和情绪，不需要拆成六句。

`source_performance_layers` 继续保存时间、参考帧、置信度和缺口原因，作为内部证据账本。SRC 只能使用 `observed / audible / not_visible / not_applicable`；`template_supplement` 不得写入 SRC。ADD 只有在用户明确授权商业化增强时才可使用 `template_supplement`，并且必须同时写 `creative_enhancement.status=user_authorized`、具体增强词和可见执行。可复制 Prompt 不输出这些状态词和审计字段；`not_visible` 与 `not_applicable` 直接省略。

### 抖音带货情绪捕捉

有人物的商业短视频镜头必须同时写：

- `persona_drive`：这一刻是什么欲望或压力推着人物行动；
- `primary_emotion`：主情绪；
- `secondary_emotions[]`：至少两个并行情绪或感受；
- `undertone`：表面情绪下压着的暗流；
- `residue`：动作结束仍留在脸、身体或声音里的余韵；
- `commercial_turn`：怎样从钩子转到馋意、证据、信任、分享或行动；
- `evidence_basis[]`：逐项回指原片时码、视线、表情、动作或声音；
- `creative_enhancement`：`none` 或 `user_authorized`，永远不和原片事实混写。

可选的情绪类别包括：馋意期待、感官击中、回味留存、挖到宝、分享冲动、认真证明的较真、熟人式亲近、反复使用后的信任、关键主张的负责感和收尾行动焦虑。每镜选择原片真正支持的类别，不要求全部出现。只有“自然、克制、真实、平稳、轻微变化”不构成情绪弧，必须失败。

每个情绪词随后必须翻译成生成模型能看到或听到的变化。例如“被酥脆击中”不是标签，而是脆响后 0.1–0.3 秒双眼短促放大、眉峰提起，随后唇角才上扬；“急着安利”体现为身体前倾、产品递近、语速加快半拍，不能只写“很兴奋”。

### 连续动作节拍

每个生成镜的 action beat 从镜内 0.00 秒连续覆盖到结束，不得留空档或重叠。每拍至少包含唯一 ID、起止时码、动作触发、具体情绪词、可见变化、声音变化、产品状态变化、镜头响应和下一动作。超过 2 秒时继续拆分；只有原片确有持续保持、停顿或闭口咀嚼才可写 `hold_reason`。

拿起/取出、掰到脆裂、两半分离、展示断面、送到嘴边、牙齿接触/咬下、产品离嘴、闭口咀嚼、恢复说话是不同不可逆事件，不能在一个几秒长节拍里“一下干到底”。禁止“按各 SRC/六层自然完成动作”“按原片节奏执行”等占位句。

### 情绪与触发

情感词与原因一起写：防备、狐疑、意外、惊喜、幸福、满足、感叹、略微兴奋、被记住后的心软、打趣、宠溺、尴尬、忍笑、得意。标明情绪基线、触发、强度、转折和落点，不写恒定“很开心”。情绪必须改变人物接下来的视线、动作节奏、发声或停顿，否则只是标签。

### 视线轨迹

至少包含两个落点或一次转移：先看盒子，再抬眼看镜头后的女生；先确认咬口，再把视线送回对方。写清停留和回看，不写“眼神自然”。

### 五官微反应

选择与情绪匹配且原片可观察的具体变化：眉峰短促抬起、上眼睑撑开、瞳孔方向移动、鼻翼轻张、单侧嘴角先起、下巴放松。只有原片确实看见吞咽时才写喉结轻动；不要每镜堆满全部器官，也不要把吃后反应当固定结尾。

### 身体和手部准备

写主动作前的准备：肩颈先松或绷、重心前移、拇指顶住侧边开口、食指与中指托底、手腕外旋、包装受力后轻回弹。动作要符合手部占用。

### 呼吸与停顿

写吸气、轻呼气、笑气、换气、欲言又止、四分之一秒或半拍停顿。它们要落在情绪转折处，不平均撒在全文。

“每镜有口播”只要求镜头分配到非空口播句段，不要求从首帧到尾帧连续发声。语义标点、对方反应、咬下、闭口咀嚼、原片确有的吞咽、掰断、撕袋和关键拟音处可以留功能性喘息；停顿中仍需有视线、手部、产品状态、拟音或微反应变化。人物在吃食动作结束后可以马上开口，不需要额外补满足反应；不要为了避免静态而堆叠无意义的大动作。

若口播容量只能靠删除这些喘息、让人物边吃边说或持续加速才能通过，标记 `BREATHLESS_SPEECH_PACKING`。先按原片/批准成片的剪辑点重分句、调整屏内与画外音或拆镜。只有项目已启用“每镜有口播”契约时，整镜没有口播句段才标记 `SHOT_WITHOUT_SPOKEN_SCRIPT`；人物只站定介绍、只有口型而没有动作或互动链仍标记 `STATIC_PERSON_INTRO_WITHOUT_INTERACTION`。

### 声音和生活口语

写音量、语速、起音、重音、尾音、连读、断句、笑意和吞音。例如：前半句压低音量试探，看到礼物后音高突然上扬；“我这个”重复起音，第二次更快，尾句在笑气里落下。

原片有人声时，把听到的音高、语速、平翘舌、前后鼻音、卷舌、语气词、连读和吞音写成“原声观察”。原片无人声或证据不足时，不留空，也不使用泛化占位句；根据人物年龄、关系、场景和情绪提出“创作提案”，至少包含：

- 一个地域口语方向，或一组明确的语音特征；
- 基础语速和情绪冲高/回落时的速度变化；
- 重音和尾音处理；
- 常用语气词、重复起音、连读或吞音方式；
- 如何避免播音腔、方言模仿过度和刻板笑料。

在对话中明确告诉用户“这是创作提案，不是原片口音识别结论”，随后直接把方案写进短卡与 Prompt。用户提出不同方向时再替换并锁定。

禁止使用“沿用原片生活口语节奏”“沿用原片生活口语风格”“沿用原片口语节奏”“保持原片口语感”等表达，也不能用“自然生活口语”“接地气地说”单独代替具体声音方案。

### 正向描述与限制词预算

- 六层正文只能使用正向导演语言，描述镜头要生成什么；“不要、禁止、不得、避免、不能、不出现”等句子不能放进六层，也不能计入表演字符。
- 先用人物关系、触发、动作链、情绪弧、产品反馈和镜头响应正面定义原片。只有正向描述仍存在真实歧义时，才在 Prompt 末尾使用 `最小纠错附录`。
- 纠错附录只保留本镜已发生过的失败、用户明确指出的错误、角色/手口资源冲突和平台必需边界；跨镜通用排除词、同义反复和为了凑长度增加的限制全部删除。
- 负面句字符默认不超过 Prompt 主体的 15%。超过时不能靠扩写水词稀释；必须删减和合并负面项，并把能正向表达的内容改写成目标状态。
- 启用 3000–4000 字契约后，若原片证据和本镜可执行内容不足以支撑下限，回到逐帧分析、动作拆解和情绪推理补证据；不能用限制词、审计字段、通用模板或重复六层原则补足。

## 8. 同步视觉证据门

台词不是悬空音轨。每句至少绑定一种同期证据：

- 被问话：听者停止或减慢手部动作，目光回到提问者；
- 看到礼物：焦点、手部犹豫和面部突变；
- “喜欢吗”：递礼者把身体微微前探，目光等待镜外反应；
- “糯叽叽”：合法咬口、浅压痕或手指受力形变；
- “都是榴莲”：镜头能看见真实断面或咬口内馅；
- “一直记得”：目光从产品回到对方，表情从惊喜转为柔软。

卖点的可见证据必须符合当前大福状态，不能为了展示满馅而让完整未破产品凭空出现断面。

## 9. 内容审核顺序

每镜人工复核：

1. 对照原声确认说话人和声源；
2. 对照画面确认谁可见、谁持机、手从哪里来；
3. 对照新版口播确认逐字、句序和归属；
4. 对照原片动作表确认无动作遗漏；
5. 对照 source inventory 确认全部源分镜、绝对时间、动作和批准图已映射；
6. 对照空间不变量确认镜外人物未被可视化；
7. 对照六层门确认表演可拍、可见、可听；
8. 对照吃食事件计划确认30秒视频数量、非连续性、节奏锚点和真实阶段；
9. 对照产品状态链确认同一实例、数量和破损连续；
10. 列出生成后仍需看像素的风险。

自动脚本只检查可编码规则。`未发现结构性阻断` 不等于人物识别正确、动作复刻完整或生成画面合格。

## 10. 必测回归场景

更新本 Skill 后至少测试：

1. 正确：男生全程画面中、女生全程镜头后；
2. 说话人错换：角色锁为女生台词，TXT 写成男生；
3. 镜外人物泄漏：写女生侧脸、嘴部、身体、倒影或自拍出镜；
4. 原片有吃但 Prompt 只写“觉得好吃”，没有复刻原片实际可见的吃食阶段；
5. 只写“开心、自然”，缺视线、五官、身体、呼吸与声音；
6. 用户 TXT 出现英文产品状态或用状态词冒充内容审核。
7. 原片无人声：必须给出具体口音创作提案并在对话中披露，Prompt 不得出现泛化口语占位句。
8. 原片吃完马上说：咬合/闭口咀嚼与屏内口播不重叠；没有吞咽或吃后反应也可通过。
9. 30秒原片只有一次吃食：按不同叙事段和新版口播锚点补两次，三个生成镜 ID 不相邻。
10. 30秒原片已有三次吃食：不得再新增第四次。
11. 两个相邻源分镜均不足4秒：合并为不少于4秒的生成镜，但两个源 ID、时间、动作和批准图全部保留。
12. Prompt 精简：删去重复限制后，核心主体、动作、产品和适用六层仍完整；整句重复填充必须被拦截。
13. 叙事优先：Prompt 先有完整的原片情境、触发、人物意图、情绪转折和镜头落点；六层融入动作链，负面句不超过主体 15%，不能用六层状态字段或限制词凑字。
