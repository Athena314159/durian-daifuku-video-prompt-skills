# 榴莲大福视频 Prompt Skills

一套可安装到 Codex 的短视频复刻与榴莲大福植入工作流。它会先分析原视频并提交原口播稿/字幕供用户修改，再锁定人物身份、出镜状态和原片动作，最后按分镜生成适用于即梦的视频 Prompt 与 TXT 交付稿。

## 两类能力与三个 Skills

这个仓库不是两个彼此独立的 Skill，而是两类能力共用三个小 Skill：

1. **视频分析与 Prompt 生成**：由 `extract-skill`（提取skill）作为主入口，调用 `director-skill`（导演skill）完成原视频分析、口播/字幕交接、拆镜、首帧与候选帧提取、动作和人物表演复刻，以及即梦 Prompt 编译。
2. **提取视频帧后替换产品主体**：由 `director-skill` 提取准确首帧与美观候选帧，再由 `product-skill`（产品skill）按产品规格、参考图角色和五形态物理连续性替换画面主体；最终结果回到主流程继续生成分镜与 Prompt。

因此，完整更新和安装时需要同时保留以下三个目录：

- `extract-skill`（提取skill）：主入口。负责原视频分析、口播回传、人物与出镜锁定、逐分镜 Prompt、质量门禁和 TXT 输出。
- `director-skill`（导演skill）：负责镜头结构、视频素材和镜头帧提取、准确首帧与美观候选帧分离、动作节拍、人物表演、口播/画外音规划和即梦工作台流程。
- `product-skill`（产品skill）：负责把图片或视频帧中的主要食品主体替换为约 7 厘米榴莲大福，并控制五种产品形态、物理连续性与人物交互一致性。

三个目录需要一起安装；主 Skill 会在适合的镜头调用另外两个 Skill 的规则。

显式调用名称为 `$extract-skill`、`$director-skill` 和 `$product-skill`。旧名称已在本次更新中停止使用；安装器使用 `--force` 升级时会安全迁移旧目录。

## 安装

要求：已安装 Codex，电脑上可运行 Python 3.9 或更高版本。

克隆仓库后，在仓库根目录执行：

```bash
python3 install.py
```

安装程序默认复制到 Codex 的个人 Skills 目录。也可以指定其他目录：

```bash
python3 install.py --target /你的/Codex/skills/目录
```

如果目标目录已存在同名 Skill，安装程序会停止且不会覆盖。确认要升级时使用：

```bash
python3 install.py --force
```

也可以手动把 `skills/` 下的三个文件夹复制到个人 Codex Skills 目录，然后重新启动 Codex。

## V2 Canonical（新版系统）

仓库现在同时提供 `video-remix-system-v2-canonical`。它是按源片证据编译的新版入口：会锁定源镜头顺序、源帧哈希、口播 line ID、人物/纯手部/微距镜头边界，并按目标时长计算吃食镜头数量。静态图层通过火山引擎 Ark 调用 Seedream 5.0；视频生成后端需要另行接入。

第一次使用新版系统，先阅读 [`skills/video-remix-system-v2-canonical/QUICKSTART_CN.md`](skills/video-remix-system-v2-canonical/QUICKSTART_CN.md)。说明书按“自测 → 编译 → 校验 → Seedream 干跑 →（有凭证时）提交静态图”的顺序写，适合不熟悉命令行的使用者。

安装新版系统：

```bash
python3 install.py --force
```

安装器会先替换同名 Skill，并保留旧目录的安全迁移逻辑；安装完成后重启 Codex。

## V3 Canonical（当前发布版）

V3 在 V2 的源帧哈希、改稿失效、Seedream 请求校验和 Canonical DOCX 门禁基础上，补充了适合新手的自然语言指挥教程与可视化流程图。V2 目录仍保留用于兼容旧项目；新项目优先调用 V3。

先读 [`docs/V3-小白操作教程.md`](docs/V3-小白操作教程.md)，再安装并调用 `video-remix-system-v3-canonical`：

```bash
python3 install.py --force
```

安装器会同时安装 V2 兼容目录和 V3 当前发布目录。静态图仍由 Seedream/Ark 执行，视频后端需要单独配置；没有生成结果时，V3 会阻断完整 DOCX，不会把缺图文档当成最终交付。

## 调用方式

把视频发给 Codex，并使用以下任一说法：

- `提取视频prompt skill`
- `调用大福的拆视频skill`
- `大福拆视频`
- `提取视频prompt`
- `换成榴莲大福逐分镜`

标准流程不会在第一次分析后直接生成完整 Prompt：

1. Codex 提交原口播稿和画面可见字幕，并标明初步说话人。
2. 用户修改口播稿并发回；若不改，也要明确确认沿用原稿。
3. Codex 锁定每位人物的性别/身份、出镜或画外位置、互动对象、口音和产品包装。
4. Codex 复刻原视频全部关键动作，在合适的镜头植入榴莲大福，并生成完整版和逐分镜版。
5. Codex 输出分镜清晰、秒数从 0 开始计算的 TXT 文件；画面禁止字幕和水印。

## 设计重点

- 不允许把画外人物写进画面，也不允许错配说话人。
- 原片出现拿、递、拆、咬、嚼、吞咽、展示等动作时，Prompt 必须完整复刻动作链。
- 人物描述覆盖情感词、五官变化、视线、呼吸/停顿、手部小动作、语气和口音，避免只有空泛的“自然”“生活化”。
- 口播稿既单独列出，也以叙事方式嵌入对应分镜 Prompt；原片没有台词时不擅自加台词。
- 产品形态全部使用自然中文描述，不在交付稿里出现内部状态名或审核占位词。
- 默认每段 2–3 句台词、单段 Prompt 不超过 4000 字，长句口播尽量控制在约 50 字以内；具体切镜仍以原视频节奏和动作连续性为准。

## 仓库边界

本仓库只包含 Skill 指令、规则、脚本和产品形态参考资产，不包含用户原视频、对话记录、生成结果、账号信息或本机绝对路径。
