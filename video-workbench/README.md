# 镜流电脑版工作台

镜流把本地 Codex 视频改款流程搬进一个可直接操控的 macOS 桌面工作台。它不是只显示运行状态的后台：用户可以在同一窗口中置入或替换 9:16 原视频、建立多个任务、选择目标人物和产品、查看逐镜进度、标记吃食与掰开、确认拆镜、检查和返工 Prompt、导入生成结果、复制图片、批准资产并完成 Word 交付检查。

新版替换操作只提供三种：**只换产品、只换头、换头 + 换产品**。不再提供整人替换，也不把“不替换”作为新建任务选项；换头始终保护原片身体、服装、动作、场景、构图和光线。

## 打开与原生文件选择

推荐在 Finder 中双击 [镜流工作台.app](./镜流工作台.app)。应用使用 macOS 原生 Mach-O/AppKit 启动入口，在自己的窗口中承载工作台，并自动启动和关闭本地执行层；不需要先开终端，也不依赖 Chrome 或 Edge 才能显示界面。若系统第一次拦截本地应用，可右键应用并选择“打开”。

`.app` 内所有文件按钮都会调起真正的 macOS `NSOpenPanel` 文件选择器，包括选择/替换原视频、上传人物参考、上传产品与分层包装参考以及导入生成结果。选择完成后，文件会进入当前可见表单并真实上传到本地项目；不是让用户手填后台路径。

也可以双击 [run.command](./run.command) 作为带可见终端日志的备用入口。备用脚本只监听本机 `127.0.0.1`，优先使用 Chrome 或 Edge 的独立应用窗口；没有这两款浏览器时使用系统默认浏览器。备用入口使用浏览器自己的文件选择器。关闭该终端即可停止备用工作台；使用 `.app` 时，关闭原生工作台窗口即可停止由它启动的本地执行层。

默认位置：

- canonical 视频项目：工作区的 `work/`
- 工作台任务、知识库和运行记录：`video-workbench/data/`
- 启动日志：`video-workbench/data/logs/`

## 项目 → 任务 → 分镜

工作台按三个可见层级组织，不再把所有状态堆在一个总览页里：

| 层级 | 用户看到什么 | 负责保存什么 |
|---|---|---|
| 项目 | 左侧项目列表和当前项目标题 | 原视频、口播、人物/产品绑定、canonical 分镜、批准资产和交付状态 |
| 任务 | 当前项目顶部的任务标签页 | 本次分析、总控执行、绑定、单镜返工或导出的阶段、进度、等待项、失败原因和事件 |
| 分镜 | 原片时间轴、SRC/ADD 卡片和右侧当前分镜 | 准确时码、动作拍、吃/掰语义、图片、Prompt、问题、版本、审批和返工范围 |

先选项目，再选该项目中的任务，最后在时间轴选择具体 SRC/ADD 分镜。右侧大图、检测、口播、Prompt 和返工操作都跟随当前分镜切换，避免把 A 项目的图、B 任务的状态或其他镜头的 Prompt 混在一起。跨项目任务可以并行；同一项目的 canonical 写任务按 FIFO 串行，读取、播放和界面轮询不占写队列。

## 9:16 原视频真实置入与替换

空工作台中央是 9:16 竖屏视频画布。点击“选择原视频”后，可用原生文件选择器置入 MP4、MOV、M4V 或 WebM，也可以把文件拖进画布。创建项目时，视频会通过 multipart 真正写入该项目的 `source/uploads/`，后端再调用 FFprobe 读取真实时长、宽高、画幅、帧率和音轨，并生成可播放的项目媒体地址。

已有项目会显示“替换原视频”。新文件同样经过真实媒体解码和探测；只有上传成功才成为当前源片。视频 SHA-256 变化后，旧口播确认、分镜分析、Prompt、检测、批准资产和 Word 授权会统一失效并留下 replacement receipt，旧文件可供审计，但不会被当成新源片的有效结果继续交付。

## 三种替换操作

- **只换产品**：选择知识库中的目标产品，原片人物身份、身体、服装、动作和场景保持不变。
- **只换头**：选择已授权人物及原片人物 owner，只替换头部身份；身体、服装、手势、产品、背景、机位和光线继续来自同编号原片首帧。
- **换头 + 换产品**：同时选择人物和产品，两套资产在同一候选图上联合审核；任一项失败都只返工当前镜头，不把局部成功的失败候选继续传给下一步。

多人原片必须明确选择要替换的 source person。作用范围可选全片、含人物镜头、指定镜头或时间范围；空的指定范围不会悄悄扩大成全片。

## 产品主体与四层包装

产品库不再用一段模糊说明混写裸产品和所有包装。每个产品可分别选择、上传和锁定：

- **产品主体**：裸产品本身的尺寸、形状、材质、状态和主体参考图。
- **独立包装 `individual_package`**：直接包住单个产品的膜袋、小包或独立袋。
- **零售盒 `retail_box`**：面向消费者的零售盒/包装盒。
- **内托 `inner_tray`**：盒内槽位、透明托盒或其他内托结构。
- **运输箱 `shipping_carton`**：装载零售盒的运输纸箱或外箱。

四个包装层各自保存尺寸、直接容纳数量、拓扑、`contains` 关系、可选材质/文字版式，以及明确标有 `packaging_layer` 的参考图。工作台返回的 `packaging_assets` 也按这四层分别展示，因此零售盒图不会冒充裸产品图，独立袋、内托和运输箱也不会被混用。一个声明存在的包装层缺参考图，或上传了该层图片却没有合同，都会停在明确的待补状态，而不是让模型自行猜尺寸、数量或包装关系。

自定义产品和人物可直接点“编辑”修改结构化资料，不需要重新上传已有图片；保存时原参考图及 SHA 保留，已经绑定项目的冻结合同不会被静默覆盖。系统内置条目保持只读，但卡片提供“复制为可编辑产品/人物”：工作台会把可确认的主体尺寸和包装事实带入新表单，用户补入自己确认的参考图后保存为独立自定义版本。

旧扁平 `package_spec` 仍可供历史项目读取；新版知识库录入和绑定使用分层包装合同。更完整的字段与 multipart 示例见 [backend/README.md](./backend/README.md)。

## 一条完整任务怎么走

1. 新建项目，用 macOS 原生文件选择器置入 9:16 原视频；也可在已有项目中真实替换源片。
2. 在当前项目“主操控”选择“只换产品”“只换头”或“换头 + 换产品”，再从项目顶部新建任务，并选择单任务总控或图像审计/文本分析并行。
3. 启动原片 intake，生成原片证据、连续口播、人物 owner 和覆盖 0 秒到片尾的 SRC/ADD 最小分镜。Codex 未在项目设置中明确开启时，任务会停在等待，不会伪装完成。
4. 从产品库或人物库自主选择目标条目。产品主体与独立包装、零售盒、内托、运输箱分别绑定；换头时同时选择已授权人物和正确的原片人物 owner。
5. 在原片播放器标记“吃”或“掰开”的准确时点。若一个镜头包含多个动作，可在当前游标处创建准确时码的拆镜预览；只有再次确认才会改 canonical 分镜，父镜旧图和旧 Prompt 不会继承为子镜完成态。
6. 在 Prompt 面板逐镜检查“情绪平、六层套话、节奏未拆、漏吃、漏掰、包装尺寸错、光影不贴场”等问题，填写可见情绪、动作拍和说话/吃食转换，再只派回当前 SRC/ADD。
7. 将即梦返回的首帧或视频导入当前分镜，填写版本与备注。导入只是结果回收，仍需逐张审核和人工批准；撤销批准会重新关闭交付门。
8. 在“批准与最终交付”核对全部 unit 的图片覆盖、有效批准、Prompt 对齐和 Word 全页视觉 QA。Word 每页以可见缩略图呈现，逐页勾选后才可批准；回执绑定当前 DOCX 与每页 SHA-256，文件一变自动失效。

项目设置中的 Prompt 字数硬门默认关闭（canonical 为 `false/0/0`），不会为了旧项目的 3000–4000 字要求注水扩写；只有用户显式打开时，上下限才同时生效。关闭长度门不会关闭情绪、动作拍、吃/掰、包装和源片证据质量门。

## 图片与 Prompt 一键复制

当前分镜大图、分镜卡、结果图库和产品/人物知识库卡片都提供“复制图片”。支持图片剪贴板的 macOS/WKWebView 会把实际 PNG 像素写入剪贴板，可直接粘贴到即梦或其他应用；若当前系统版本不开放图片剪贴板，则自动复制该本地图片地址，并在界面明确提示，不会静默失败。

Prompt 面板提供“一键复制 Prompt”，复制的是当前所选生成段正在显示的 canonical 可复制内容。复制动作跟随当前项目、任务和分镜上下文，不需要到后台文件夹寻找 Markdown，也不会用摘要替代逐镜 Prompt 原文。

## 能力边界

工作台能够编排本地确定性脚本和用户显式开启的 Codex CLI。图像生成、视频生成和自动提交即梦需要另接对应适配器；未配置时界面会明确显示“未配置/等待”，不会用假进度或占位图冒充已经生成。即梦等外部生成产物可以通过“导入生成结果”回收到同一套项目、任务、分镜、版本、哈希和批准链，但不再单独占用顶部栏目。

已提供可双击的本地 macOS `.app` 启动包，入口为原生 AppKit/WebKit 应用。它经过本机 ad-hoc 签名，但不是 Apple Developer ID 公证、可对外分发的商业安装包；执行层和项目数据仍完全落在本地目录，也不会向局域网开放端口。

开发与 API 说明见 [backend/README.md](./backend/README.md)。
